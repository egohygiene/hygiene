## Immutable implementation and source gate

`.github/workflows/publish-pages.yml` is the sole Pages publisher. The existing
manual policy-release handoff remains separate. Every Relay call pins merged
`6cddad3124bdda1b1e3d54a40931f23322b7be26` (PRs #154 and #155), including the
native EgoLint owner support merged at `72267fd0a371da6d94922cbc6bd3dedddb68df30`.

1. PR, main push and manual runs validate the publisher and local contracts.
2. Relay's read-only advisory workflow inspects the exact caller revision using
   `.config/egolint/repository-intelligence.toml`. It retains its real report
   even when ADR-0001 makes the corpus nonconformant.
3. The caller selects only explicit `passed`, untruncated, public ADR coverage
   for the same repository and revision. The overall architecture result can
   remain incomplete because contract/diagram adoption is unknown; that is
   never presented as complete architecture conformance.
4. Only an admitted source enters Relay's strict `collect-adrs` builder, with
   explicit canonical-owner mode and the existing Identity ADR-017 key. The
   builder independently rejects incomplete, invalid or stale ADR coverage.
5. Hygiene composes only the landing and aliases. Relay captures their baseline
   and verifies preservation, source binding, every bundle route and freshness.
6. A transport inventory seals every file. The exact site and composition
   evidence are retained for 90 days. A deploy job downloads that run's artifact
   by ID and rechecks both local transport and shared composition evidence.

An advisory job succeeding is **not** source admission. When ADR coverage has
not passed, admission reports **publication blocked**, and build/deploy skip.
Missing reports or infrastructure failures cannot produce an artifact.

## Deployment and evidence

Only main pushes or manual main runs in `egohygiene/hygiene` can reach deployment.
PRs have read permission only. Pages write/OIDC permissions and the
`github-pages` environment exist only on the deploy job. Serialized publication
does not cancel a deployment already in progress.

Before deployment, the caller checks the actual HTTPS origin. A prior
`publication.json` must describe a completely downloadable, checksum-valid
site; those exact bytes are retained as the recovery artifact **before** the
deployment. Only a 404 for both manifest and root establishes first deployment.
An existing unmanifested site, TLS error or unverified recovery prevents a new
deployment. Provisioning a certificate may therefore need completion in Pages
settings before the first deployment can proceed.

After `deploy-pages` succeeds, verification compares the canonical manifest and
every public file to the sealed local bytes over verified HTTPS. `CNAME` and
`.nojekyll` are GitHub control files; they are retained and checked locally,
explicitly excluded from public-route claims. The consumer-owned receipt binds
the real workflow run/attempt, source, generator, file inventory, verification
time and actual recovery point. No success receipt is written on drift/failure.
Always-run artifact preservation retains available composition/recovery evidence
even if deployment or live verification fails. Consult the provider's actual
job conclusion; absence of a success receipt does not prove the provider left
the previous deployment unchanged.

The shared deployment-receipt schema requires a prior revision/digest. The
consumer receipt here deliberately uses `hygiene.pages-deployment/v1`, so a
first deployment can truthfully record `first-deployment` with no fictional
prior SHA. Shared collection/build/composition contracts remain unchanged.

## Recovery

For a replacement deployment, download the `hygiene-pages-recovery-<run>-<attempt>`
artifact. Its `site/` contains the complete prior site and manifest, with
provider control files reconstructed only when their declared hashes match.
Restore those retained bytes through GitHub Pages in a separately reviewed
recovery action; preserve the recorded prior source/Relay pins rather than
pretending an old site was rebuilt from the new source. Retain a new receipt
after verification. Artifacts expire after 90 days; archive a needed recovery
point before expiry. No automatic recovery job is installed by this change.

For first deployment, there is no earlier site to restore. Recovery is to
unpublish that deployment through GitHub Pages, then fix and publish a successor.
This runbook does not claim an exercised provider rollback before a site exists.
